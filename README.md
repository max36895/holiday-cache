# Праздничный Тайник — групповые игры для тех, кто сидит в разных мессенджерах

<p align="center">
  <img src="assets/logo.svg" alt="Праздничный Тайник" width="540">
</p>

Бот на [umbot](https://github.com/max36895/universal_bot-ts): люди из **Telegram, VK, MAX и Алисы** играют в
одну игру по коду комнаты. В тайнике — Тайный Санта, дни рождения команды, анонимные валентинки,
тайный даритель и сбор на встречу: всё спрятано до назначенного часа. «Создать игру» открывает выбор
с описаниями режимов.

Организатор создаёт игру и пересылает приглашение с кодом. Каждый участник пишет код боту в своём мессенджере
и отвечает на пару вопросов. Дальше бот ведёт игру сам: жеребьёвка, напоминания, анонимные сообщения.

Развёртывание на своём сервере: reverse proxy с HTTPS перед ботом (бот работает по подпути
существующего домена — отдельный домен и сертификат не нужны), systemd-юнит с `NODE_ENV=production`,
cron-задачи из раздела ниже и бэкап файла SQLite.

## Запуск за 5 минут

Нужен Node.js 22 или новее.

```bash
npm install
cp .env.example .env   # заполните токены нужных мессенджеров
npm run build
npm start
```

Бот слушает `http://0.0.0.0:3000/` — один адрес для всех платформ, umbot сам определяет, откуда пришёл запрос.
Для мессенджеров нужен публичный HTTPS-адрес (reverse proxy перед ботом).

| Платформа | Что сделать                                                                                         |
| --------- | --------------------------------------------------------------------------------------------------- |
| Telegram  | `TELEGRAM_TOKEN`, затем `npx umbot webhook telegram https://<домен>/` — вебхук с секретом           |
| VK        | Callback API сообщества на `https://<домен>/`; `VK_TOKEN`, `VK_CONFIRMATION_TOKEN`, `VK_SECRET_KEY` | Приглашение ведёт на `vk.me/<сообщество>?ref=<код>` — umbot передаёт код боту |
| MAX       | `MAX_TOKEN`, затем `npx umbot webhook max https://<домен>/`                                         |
| Алиса     | В консоли Яндекс Диалогов укажите Webhook URL `https://<домен>/`; токен для ответов не нужен        |

Перед запуском проверьте настройку: `npx umbot doctor` проверяет токены, вебхуки и то, что `.env` не попадёт в git.

Все переменные — в [.env.example](.env.example). Главные:

| Переменная                                                          | Зачем                                                        |
| ------------------------------------------------------------------- | ------------------------------------------------------------ |
| `SQLITE_FILE`                                                       | файл базы SQLite. Пусто — файловая БД umbot (для разработки) |
| `TELEGRAM_BOT_NAME`, `VK_GROUP`, `MAX_BOT_NAME`, `ALISA_SKILL_NAME` | ссылки на бота в тексте приглашения                          |
| `PRIVACY_POLICY_URL`                                                | ссылка на политику конфиденциальности в меню и «помощи»      |
| `SEND_DELAY_MS`                                                     | пауза между сообщениями рассылки (по умолчанию 100 мс)       |

### Задачи cron

```bash
*/5 * * * * cd /opt/rooms-bot && npm run tick      # расписание режимов и отложенные сообщения
0 4 * * *   cd /opt/rooms-bot && npm run cleanup   # удаление игр с истёкшим сроком хранения
0 5 * * *   cd /opt/rooms-bot && npm run stats     # цифры сезона: комнаты, участники, мессенджеры
```

`tick` вызывает режимы, у которых наступило время (напоминание Санты за 2 дня до обмена), и доставляет
отложенные анонимные сообщения. Повторный или прерванный запуск не отправит сообщение второй раз: ключ каждого
сообщения записывается в журнал `sendLog` до отправки. Цена такой гарантии — сообщение может не уйти, если
процесс упадёт между записью ключа и отправкой.

Задачи работают с той же базой, что и бот: изменения одной комнаты идут по очереди через блокировку в таблице
`locks`. С SQLite задачи запускают при работающем боте. Файловая БД umbot рассчитана на один процесс —
с ней задачи запускают только при остановленном боте.

Санта и тайный даритель хранятся 30 дней после даты обмена (или 90 дней после создания без даты).
Валентинки и встречи — 30 дней после события или завершения организатором, что позже.
Бессрочные комнаты дней рождения задача `cleanup` не трогает. Организатор может удалить любую комнату вручную.

## Дополнительные режимы

### Дни рождения команды

Организатор задаёт название и пояс IANA (например `Europe/Moscow`); может участвовать или только управлять.
При входе участник указывает имя, день и месяц рождения без года. Даты видны всем через кнопку
«Ближайшие дни рождения» в карточке, свою дату можно изменить. Состав комнаты всегда открыт.
Для каждого именинника остальным участникам отправляются отдельные напоминания за 7 дней и в сам день
в 10:00 по поясу комнаты. В невисокосном году 29 февраля отмечается 28 февраля.
Прошедшие напоминания новым участникам не отправляются; изменение даты действует только на будущие события.
После выхода, исключения или удаления данных участник исчезает из календаря.

### Анонимные валентинки

Организатор задаёт название, пояс, дату и время доставки, своё участие. Участники вводят имя и могут
отправить другим участникам до 20 анонимных сообщений по 500 символов. Себе отправлять нельзя.
До срока получателю ничего не показывается, автор может отменить сообщение через «Мои сообщения».
В назначенное время приём прекращается независимо от запуска cron; ближайший `tick` доставляет накопленное.
Сообщения доступны во входящих карточки, включая более ранние страницы. Ответы отключены.
Получатель может заблокировать автора и пожаловаться; организатор получает текст без имени автора
и может исключить его по жалобе. После срока организатор завершает комнату.

### Тайный даритель

Универсальный вариант Санты для любого праздника: название, повод («8 марта», «День рождения»),
необязательные бюджет и дата вручения, имена и пожелания участников. Использует адаптер над `SantaMode`,
не меняя его файл и правила комнат `santa`.
От трёх участников — жеребьёвка без пар с самим собой, анонимный вопрос подопечному, изменение пожелания,
отметки «подарил»/«получил», повторная доставка результатов и напоминание за 2 дня в 10:00.
До завершения организатор видит только состояние подарков без раскрытия пар; после — сводку пар.
До жеребьёвки можно выйти; после неё доступна команда «удалить мои данные», затронутые даритель
и подопечный получают уведомления без раскрытия личности дарителя. «Сыграть ещё раз» создаёт пустую
новую комнату с прежними правилами; дату обмена нужно задать заново — дата прошлого обмена
не переносится.

### Сбор на встречу

Название, пояс, дата и время, место, необязательные сумма взноса и инструкция по передаче денег.
Участник выбирает «Приду», «Не приду», «Пока не знаю», меняет ответ до завершения и, если есть взнос,
может поставить или снять отметку «Я сдал». Это заявление участника: бот не принимает деньги,
не переводит их и не подтверждает платежи. Организатор видит ответы, счётчики и отметки.
Изменения места и даты отражаются в карточке и рассылаются участникам. За 24 часа до встречи
напоминание получают «Приду» и «Пока не знаю». После встречи организатор завершает комнату.

### Расписание и платформы новых режимов

Дополнительных переменных окружения или зависимостей нет: используются существующие токены, ссылки,
хранилище и задачи `tick`/`cleanup`. Пояс задаётся при создании; дата без года означает ближайшую дату,
дата и время вводятся, например, как `14.03.2027 19:00` или `сегодня в 19:00`.
Проверяется корректность даты и пояса; прошедшее время отклоняется целиком — не только дата.
При cron раз в пять минут фактическая отправка может задержаться на интервал запуска.

Алиса не пишет первой: календарь, данные встречи, подопечный и доставленные валентинки доступны из
карточки комнаты. Названия кнопок последнего ответа распознаются текстом; при одинаковых подписях
нужно выбрать кнопку. Общие «Мои игры», приглашения и удаление данных работают для всех режимов.

Расписание и очередь сохраняются в БД, перезапуск приложения их не теряет. Пропущенные запуски
календаря обрабатываются по сохранённому курсору; напоминание о встрече после самой встречи уже не отправляется.
Повторный запуск не повторяет рассылку: используются курсор/флаг режима и ключи `sendLog`.
Для валентинок статус сообщения сохраняется перед отправкой. Это действующая модель доставки,
а не гарантия получения: сбой между записью курсора, флага, статуса или журнала и отправкой может
привести к потере уведомления. Повторный запуск автоматически такую потерю не исправляет.

Все режимы реализованы через `IMode`; БД, блокировки и отправка остаются в ядре. Добавлены общий тип
вопроса `timezone`, необязательный `relayDeadline` и текстовый вызов существующих обработчиков кнопок.
У Санты срок приёма не задан, его прежние правила не меняются. Клиентского JS-бандла здесь нет:
код работает на сервере. Новые зависимости и клиентский код не добавлены; сетевой обмен увеличивается
только за счёт запрошенных меню, ответов и уведомлений новых режимов.

Перед запуском можно проверить производительность: `npm run loadtest` — жеребьёвка на 100 участников
и поток входов на SQLite в памяти. Рассылка результатов на 100 человек занимает ~10 секунд с паузой
по умолчанию (`SEND_DELAY_MS=100`): темп платформ (Telegram — 30 сообщений в секунду) выдерживает сам umbot.

## Тайный Санта

- **Создать игру** — название, бюджет и дата обмена (оба можно пропустить), участвует ли организатор сам.
  Бот присылает карточку игры с кодом и отдельным сообщением приглашение для пересылки.
- **Войти** — прислать боту код (регистр не важен) или открыть ссылку из приглашения; имя и пожелание.
- **Организатор** видит участников, исключает до жеребьёвки, проводит жеребьёвку (от 3 участников), переносит
  дату обмена (до и после жеребёвки — дарители узнают о переносе), повторяет отправку тем, кому не дошло,
  завершает или удаляет игру. После завершения — «Сыграть ещё раз»: новая игра с теми же правилами и новым кодом.
- **Участник** меняет пожелание (и после жеребёвки — его Санта получит обновление) или выходит до жеребёвки;
  после — смотрит «Кому я дарю?» и может анонимно спросить подопечного о подарке. За 2 дня до обмена бот
  напоминает дарителям. Если Санта вышел из игры, его подопечный узнаёт об этом сразу.
- **Вручение подарков** участники отмечают кнопками «Я подарил подарок» и «Я получил подарок», а организатор
  по кнопке «Кто кому дарит» видит, у кого подарок вручён, а у кого ещё нет — и кому напомнить.
- **Анонимные сообщения** видны получателю и во «Входящих сообщениях» карточки игры — это единственный канал
  для Алисы, которая не умеет получать сообщения первой. Получатель может переслать организатору жалобу:
  организатор видит текст, но не автора, и может исключить автора кнопкой. Поэтому текст хранится до удаления игры.
- **Игра в наборе без даты обмена больше недели** — организатору придёт напоминание, один раз.
- **«удалить мои данные»** — игры организатора удаляются целиком, из наборов человек выходит, в проведённых играх
  стираются его имя, id, ответы и анонимные сообщения (написанные и полученные), а его даритель получает
  уведомление.

Всё доступно кнопками. Текстом работают «меню», «создать», «мои игры», «помощь», «удалить мои данные», а в
выбранной игре — название любой кнопки режима («кому я дарю»): так игра работает и голосом в Алисе.

## Ограничения

- **Только личные сообщения** с ботом: в групповые чаты бот не добавляется.
- **Алиса не умеет писать первой.** Результаты, напоминания и анонимные сообщения участник из Алисы видит
  по кнопкам в карточке игры, а в отчёте организатора он отмечен как «не доставлено».
- **Один процесс бота.** Задачи cron — отдельные процессы, с ботом их согласует блокировка в базе; несколько
  процессов самого бота (кластер, serverless) не поддерживаются: счётчик неверных кодов живёт в памяти.

## Устройство

```
src/
  index.ts                 — запуск: настройки и bot.start()
  app.ts                   — сборка: платформы, БД, rateLimiter, диалоги, сервисы
  controller/              — диалоги: меню, мастер вопросов, вход по коду, карточка, действия, пересылка
  core/
    RoomService.ts         — комнаты и участники, права, применение результата режима
    Wizard.ts              — вопросы мастера: текст, число, дата, день и месяц, дата и время, выбор, список
    Notifier.ts            — рассылка через bot.send(), учёт доставки, отчёт организатору
    Relay.ts               — анонимная пересылка: ответ, жалоба, блокировка, отложенная доставка
    Scheduler.ts           — комнаты с наступившим nextRunAt → onSchedule режима
    RoomLock.ts            — очередь изменений комнаты в процессе и между процессами
    Store.ts, models.ts    — таблицы через Model из umbot
    db.ts                  — описание таблиц, выбор БД, создание таблиц
  modes/
    IMode.ts               — контракт режима
    registry.ts            — включённые режимы
    shared/draw.ts         — жеребьёвка: одна цепочка и две группы
    santa/                 — Тайный Санта
  jobs/                    — tick.ts, cleanup.ts и stats.ts для cron
tests/                     — сценарии через BotTest, режимы и жеребьёвки — юнит-тестами без БД и сети
```

**Режим не пишет в БД и не отправляет сообщения.** Он описывает вопросы, кнопки для человека в текущем
состоянии комнаты, обработку нажатий и расписание, а возвращает `IModeResult`: ответ, изменения комнаты и
участников, отметки и сообщения. Ядро проверяет права (доступно только то, что режим показал этому человеку),
сохраняет изменения, пересчитывает срок жизни и время следующего запуска, делает рассылку. Поэтому режим
тестируется без БД и сети, а новый режим — папка в `modes/` и строка в `modes/registry.ts`. В тестах есть
тестовый режим (`tests/fixtures/partyMode.ts`), который задействует все возможности ядра.

Таблицы общие для всех режимов: `rooms`, `participants`, `marks` (голоса, «скинулся», ответы), `relays`
(анонимные сообщения; текст хранится до удаления комнаты), `blocks`, `sendLog`, `locks`. Данные конкретного режима — в JSON-полях
`rooms.settings` и `participants.profile`.

Жеребьёвка — алгоритм Саттоло на `crypto.randomInt`: все участники встают в одну цепочку, поэтому никто не дарит
себе и (от трёх участников) нет пар «дарят друг другу». Для двух групп — равномерное распределение, при неравных
группах кто-то дарит двоим или дарят вдвоём.

Код использует только публичный API umbot: `umbot`, `umbot/plugins`, `umbot/middleware`, `umbot/utils`,
`umbot/test`.

## Разработка

```bash
npm test               # jest: сценарии через Алису и Telegram, ядро на тестовом режиме, SQLite
npm run lint
npm run prettier
npm run check          # всё сразу, как в CI
```

Сценарные тесты гоняют настоящий `createApp()` на `BotTest`: Алиса возвращает ответ сразу, а запросы к API
Telegram, VK и MAX перехватывает подменённый HTTP-клиент umbot — сеть не нужна. Время подменяется, поэтому
расписание проверяется без ожидания.
